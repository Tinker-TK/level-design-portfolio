## 0. 一句话结论

**Apex 的关卡不是"让人藏起来的地图"，而是一台"制造可预期冲突的机器"。**

它有四个部件，缺一不可：

| 部件 | 作用 | 对应设计手段 |
|---|---|---|
| **拉力** | 把人从安全处拉出来 | 资源、信息、圈、空投、PVE、微观目标物 |
| **推力** | 把人推进必须近战决胜的空间 | 外围高内部低的 POI、房区、视野压迫、掩体密度 |
| **切分** | 把连续地图切成可读的节拍，同时切断无意义枪线 | 隔离带、咽喉点、空白区 |
| **计时** | 给整局一个不可逆的时间轴 | 缩圈、转移工具、决赛圈地形 |

由此得到本文的总原则：

> **每一块地形都要能回答三个问题：它把玩家往哪推？它让玩家看到什么？它让哪条枪线失效？**
>
> 答不上来的地形，就是"美术"，不是"关卡"。

## 1. 五条第一性约束

在画第一条线之前，先把这五条约束过一遍。它们不是设计目标，而是**物理定律**——违反它们的设计，上线后一定会以"节奏拖沓 / 劝架过多 / 某点无敌 / 没人去"的形式还回来。

### 1.1 战斗驱动，而不是生存驱动

Apex 的地图明显小于同类产品：公开统计约 2.2–2.7 km 见方、60 人，密度远高于 PUBG 的大图；POI 之间常常一分钟内可达，有位移技能时十几秒就能到[10][11]。这不是"地图做小了"，而是把"跑图—偶遇—猝死"的生存节奏，改造成"搜索—交火—再交火"的战斗节奏。

**推论**

- 地图的 KPI 不是"玩家能活多久"，而是"多久遇到一次有意义的战斗"。
- 任何让玩家长时间无事可做的区域都是缺陷，不是留白。
- "安全"本身也要被设计成一种稀缺资源，而不是默认状态。

### 1.2 长 TTK + 击倒/复活，决定必须有"近距离闭环"

Apex 的 TTK 长，倒地还能被队友拉起；远距离击倒往往无法转化成人头[9]。所以地图必须提供一类**近距离闭环空间**：掩体密集、垂直度高、交战距离短，让高机动 3C 和长 TTK 的拉扯有用武之地。有拆解者估算，约 80% 的战斗发生在这样的区域里[9]。

**推论**

- POI 的核心价值不是"好看"，而是提供这种闭环空间。
- 只有远距离枪线的开阔地是"缓冲区"，不是"战斗区"；它的职责是让人通过、观察、决策。
- 评价一个 POI，先问"这里能不能打完一场完整的 3v3"，再问"这里好不好看"。

### 1.3 没有伤害衰减，所以必须用地形"关掉"远距离枪线

Apex 枪械基本没有距离衰减（旧版滋崩除外）[9]。远距离枪线天然强势，只能靠地形来限制：山脊、裂谷、建筑墙、城墙。

**推论**

- 隔离带不是美术装饰，是枪械平衡的一部分。
- 每个 POI 的朝向必须明确：哪些方向可以被抽枪，哪些方向绝对安全。
- 如果一张图"到处都能被 200 米外打到"，这张图的近战设计一定是失效的。

### 1.4 高机动 3C 与传奇差异，要求"垂直度 + 保底路线"

滑铲、攀爬、绳索、跳塔、重力炮让地图立体；但传奇之间的机动差异巨大。官方谈 E-District 时给出的判断顺序是：

先问"玩家在这上面会有什么感受"，再问"Horizon 这样的传奇能不能上来"，最后必须确保"没有位移能力的传奇有办法应对"——这些考虑优先于真实感[1]。

**推论**

- 垂直度必须配"保底路线"（楼梯、坡道、绳索、跳塔），否则非机动传奇被判死刑。
- 高点的价值要按"到达成本"定价：容易到达的高点，不能同时拥有全图视野。
- 每新增一种移动方式，都要检查它是否让某类传奇"无解"或"失业"。

### 1.5 60 人、小地图、单局 20 分钟量级，第三方是常态

20 队、60 人、单局 20 分钟量级，意味着"劝架"不是意外，而是常态。设计目标不是消灭第三方，而是**管理第三方**：让它在可预期的时间、可预期的方向发生。

**推论**

- 一场战斗的"可被介入时间"是核心参数：结束太快没有劝架，太慢会被无限劝架。
- 转移工具越"点对点"，对手越能预判；越自由，越容易"无预警第三方"（见 2.6）。
- 决赛圈必须能容纳"多队残编共存"的局面，而不是"一队清场"。

> **本节验收问题**
> 1. 这张图里，玩家平均多久遇到一次有意义战斗？最长的"无事可做"是多久？
> 2. 有没有哪个 POI 的远距离枪线无法被地形切断？
> 3. 非机动传奇在这张图上，是否每条路线都有保底方案？

## 2. 核心模型：流、节拍、注意力

### 2.1 三种流动动机

玩家在图上移动，只有三个理由：**资源、信息、圈**[11]。

- **资源**：落地、补给、升级、抢空投。
- **信息**：枪声、脚步、信标、控制台、PVE、队友标记。
- **圈**：唯一不可逆的全局压力。

设计动作：给每个区域标注"它靠哪种动机驱动人流"。如果一个区域三种都不占，它就是死区。

### 2.2 区域体量决定停留时长

拆解文章给出的公式很实用[11]：

> **区域体量 = 面积 × 战略优势 × 资源量**
>
> 体量越大，玩家停留越久；停留越久，全图流动越差。

所以"资源丰富 + 面积大 + 易守难攻 + 地图中心"的 POI，会变成"所有人围着它打"的黑洞。Apex 的常规做法是**只给两样，不给三样**：大 POI 往往资源多但不在中心，或位置好但资源一般。

设计动作：给每个 POI 写一个"预期停留时长"（例如 60–90 秒 / 120–180 秒），再用资源量、地势、出口数去凑这个数。

### 2.3 资源分布的"地图信任"三规则

Apex 的资源分布有一条隐含契约[11]：

1. **资源只在 POI 里**，POI 之间的野区基本没有资源；
2. **资源一定显眼**，在箱子、货架、光柱里，不在偏僻角落；
3. **资源分布有规律**，同类建筑给同类资源。

效果是：玩家移动时不需要"探索地图"，只需要"做决策"。节奏因此变快，注意力因此留给战斗而不是搜刮。

设计动作：如果你的地图上出现"这个角落居然有紫甲"的情况，说明规则破了，玩家的移动会变慢、变犹豫。

### 2.4 节拍单元：POI—空白区—咽喉点—空白区

Apex 的地图节奏，可以拆成同一个单元不断重复[11]：

```
[POI] ──空白区（加速/观察）──> [咽喉点（紧张峰值）] ──空白区（呼吸）──> [POI]
```

- **空白区**：视野好、掩体少、没有资源 → 玩家加速通过，同时暴露在他人视野里。
- **咽喉点**：地形收窄、视野收紧 → 紧张峰值，玩家提高警惕、准备战斗。
- **通过咽喉点后的空白区**：视野重新打开，玩家快速获取信息、做下一个决策。

多个 POI 的节拍叠加，就构成整张图的"心电图"。**地图设计的好坏，很大程度上是这条心电图的波形设计。**

### 2.5 缩圈是总节拍器

缩圈是唯一不可逆的压力源。圈越小，可绕行路径越少，越难避战[11]。第三个圈的面积已经接近一个大 POI[11]。

设计动作：把每个圈层依次叠在同一张图上，检查每一圈是否都具备：

- 可守的点位（不是只有平地）；
- 可转移的路线（不是只有一条桥）；
- 可被劝架的战斗（不是"谁先打谁死"）。

### 2.6 转移工具是节奏旋钮，而且必须"可预测"

| 工具类型 | 特点 | 对第三方的影响 |
|---|---|---|
| 点对点（重力炮/发射器） | 快、有声音、落点固定 | 对手可预判 → 降低"无预警第三方"[6] |
| 自由落点（跳塔/气球） | 灵活、方向不可预测 | 对手难预判 → 第三方成本高 |
| 载具 | 改变尺度感、可载全队 | 可能"绕过所有关卡"，需要限速/限量 |
| 绳索/滑索 | 双向、可被架 | 天然的咽喉点，适合做"高风险捷径" |

Storm Point 用重力炮替换跳塔，官方给出的理由正是：**保持快速转移，同时让移动对对手可预测，以减少负面第三方体验**[6]。

设计动作：每张图的转移工具要有"主节奏"和"例外"。全是自由落点，地图会变成"随机空降"；全是点对点，地图会变成"固定传送带"。

> **本节验收问题**
> 1. 画出这张图的"节拍心电图"，它有没有明显的"长平段"？
> 2. 每个 POI 至少有一种"拉动人流"的理由吗？
> 3. 转移工具是让战斗更可读，还是更随机？

## 3. 宏观层：全图

### 3.1 参数基准

以下区间来自公开资料与拆解文章的折算，作为**起点锚点**，不是 Apex 官方数值；用到你自己的项目时，请先用灰盒实测校准（见第 8 节）。

| 参数 | Apex 量级 | 说明 |
|---|---|---|
| 地图边长 | 2.2–2.7 km | 第三方统计，60 人[10] |
| 玩家密度 | 约 8–12 人/km² | 由边长与人数折算 |
| POI 总数 | 15–22 | E-District 为 17 个 POI + 多个营地[3]；Olympus 改版后 22 个[4] |
| 高级资源区 | 4–6 个，多在外环 | 避免"中心既富又热"[10][11] |
| 相邻 POI 边缘距离 | 150–350 m | 跑动 25–60 秒（约 6 m/s），技能位移 8–15 秒[10][11] |
| 单局时长 | 20 分钟量级 | 多个圈层 + 决赛圈 |

### 3.2 地图演化史：每一作押了什么注

| 地图 | 设计赌注 | 代价 / 结果 | 可复用经验 |
|---|---|---|---|
| **诸王峡谷**（首发） | 最小、最紧凑；高级区多、普通区少，前期尽量分散玩家[11] | 节奏最快、劝架最凶；中期压力大；S14 让 Skull Town 以 Relic 形式回归，官方称目的是改善 "map health"[13] | 小图必须靠"高级区数量"和"落点密度"分散前期流量[11] |
| **世界尽头**（S3） | 密集城市 CQC + 与 KC "房间式 POI"不同的开阔地 + 裂谷分割拉长交战 + 火车动态地形[5] | 开阔地让转点可读，但暴露风险高；火车制造动态焦点 | 用"开阔"传递信息，用"裂谷"制造技能舞台，用"动态地形"制造全图事件 |
| **奥林匹斯**（S7） | 空中城市、载具（三叉戟）、强垂直、易跌落 | 掩体不足、部分 POI 过强/过弱；S27 大改：降高度、加遮挡、补 POI、移 POI[4] | 美学优先的地图，要在"竞技公平"上补课；高差与掩体必须成对出现 |
| **风暴点**（S11） | 最大地图、PVE、重力炮替代跳塔、强垂直[6][12] | 用"可预测机动"降低无预警第三方；开发时就为后续"自然生长"预留接口[12] | 大图靠"更多咽喉点 + 点对点机动 + PVE"维持节奏 |
| **残月**（S15） | zip rails、更大的 POI、兼顾 LTM[14][18] | 连通性过强会稀释 POI 边界；S21 大改后被形容为"像一张新图"[17] | 连通工具是双刃剑：快，但会让"POI 攻防"退化成"过路战" |
| **电气区**（S22） | 都市垂直、夜间、17 POI + 营地、重力发射器[2][3] | "缓冲区/交战区"界限被批评模糊[9]；夜图可读性是专门课题[3] | 都市图要用"墙/天桥/地下"制造层次，而不是用建筑把地图填满 |

### 3.3 POI 的数量、等级与分布

- **分级**：建议用 S / A / B / C 或"高级区 / 普通区 / 野区 / 野狗点"四档。
- **外环分布**：高级资源区多在地图外围成环，航线两端必须各有高级区，满足"落地架 / 稳健发育 / 打野"三种落点期待[11]。
- **中心处理**：中心区域已经靠"战斗密度"提供护甲成长，如果再把最高级资源堆在中心，会形成"中心既富又热"的双重极化，边缘玩家被碾压[10]。所以中心放"高风险高价值"的中等资源，而不是"最安全最富"。
- **象限均衡**：每个象限 3–5 个 POI，避免"半张图没人"。
- **野狗点**：把无资源的咽喉点改造成 POI，是应急的节奏工具，但跳这里的队伍体验极差，只能少量使用[9]。

### 3.4 地形骨架

先定"骨架"，再填 POI。Apex 常用四类骨架：

| 骨架 | 作用 | 例子 |
|---|---|---|
| **山脊** | 隔离带 + 视野墙，切断枪线 | 风暴点的山口 |
| **裂谷 / 峡谷** | 硬边界 + 拉长交战距离 + 给技能创造舞台 | 世界尽头的裂谷[5] |
| **水系 / 道路** | 软引导，告诉玩家"路在哪" | 奥林匹斯的水道 |
| **城墙 / 建筑墙** | 都市图的"人工山脊" | 电气区中央的大墙[3] |

地形要能被"三读"：

- **10 秒读轮廓**：从跳伞/远处能看出这是什么地形；
- **30 秒读路线**：落地后能判断"往哪走、哪里能打"；
- **3 分钟读攻防**：打起来后能判断"哪边是高点、哪里能绕后"。

### 3.5 航线与落点菜单

航线是随机的，但落点菜单必须是设计好的。至少覆盖四类：

1. **Hot drop**：高资源 + 高密度，落地就打架；
2. **稳健发育**：中等资源 + 多出口，能搜能跑；
3. **野区**：低资源 + 高隐蔽，适合慢节奏；
4. **高风险高收益**：位置关键但难守（如中心塔、保险库）。

检查方法：随机抽 10 条航线，看每条航线是否都能支持这四类选择；如果某条航线只能"要么 hot drop 要么打野"，这条航线的体验就是残缺的。

### 3.6 决赛圈预设

决赛圈不能靠"随机到哪算哪"。建议预设至少三类终局地形：

- **室内多层**：考验房区攻防、垂直配合；
- **半开放高地**：考验高低差与转移；
- **开阔掩体群**：考验枪线与投掷物。

用"圈层叠加图"检查：最后三个圈是否覆盖了不同地形，而不是永远在山顶或永远在房顶。

### 3.7 可生长性

Storm Point 在开发时就明确：地图要能"自然生长"，而不是"炸掉重建"[12]。后来的 Broken Moon 用 zip rails 和更大的 POI 继续演化[14]，电气区则把"都市垂直"推到新极限[1]。

设计动作：

- 预留 2–3 个"可扩展地块"（新 POI、地下层、可封闭通道）；
- 保证新旧衔接处的 POI 价值不被打破；
- 每次加内容，先问"它会不会让某条旧路线变成唯一最优解"。

> **本节验收问题**
> 1. 随机 10 条航线，落点菜单是否完整？
> 2. 高级区是否在外环成环？中心是否"既富又热"？
> 3. 最后三个圈，是否覆盖了不同地形？

## 4. 中观层：POI

### 4.1 POI 的三项职能

一个合格的 POI 同时承担三件事[11]：

1. **地标**：远处能看见、能指路（"我们去那个圆塔"）；
2. **资源**：提供拉力，决定玩家为什么来；
3. **战斗体验**：提供一段有特色的攻防，决定玩家为什么记得它。

三项缺一，POI 就会退化成"资源箱"或"景点"。

### 4.2 结构模板

```
┌──────────────── 外围缓冲区（观察 / 发起进攻）────────────────┐
│   入口 A           ┌──────── 主区（地标 + 主资源 + 独特战斗）────────┐
│                    │        次区 1        次区 2                    │
│   入口 B           └──────────────────────────────────────────────┘
│                   出口 C                        出口 D
└──────────────────────────────────────────────────────────────┘
```

- **主区**：地标、主资源、独特战斗体验（例如一个可上下的中央塔）。
- **次区**：休整、分散流量、给主区提供侧翼路线。
- **外围缓冲**：地势略高、掩体少，用来观察和发起进攻。
- **入口/出口**：至少 2 个，最好 3–4 个，且风险不同。

### 4.3 推—拉模型：外围高、内部低

Apex 的 POI 常见结构是"外围高、内部低"[9]：

- **攻方**从外围高地进入，天然拥有"高打低"的优势；
- **守方**退入房区，用掩体和垂直结构抵消高地劣势；
- 战斗因此被"推"进房区，形成高质量的房区攻防[9]。

这就是 POI 的"拉力 + 推力"：

- 资源把人**拉**进来；
- 外围高地 + 视野把人**推**进房区；
- 房区结构提供"必须近战解决"的闭环。

### 4.4 高地悖论：不能"又难攻、又全图视野"

如果守方同时拥有"易守难攻"和"俯瞰四方"，这个 POI 就会变成"没人敢来"的死点。旧版诸王峡谷的"牢笼"就是反例：高塔让占据它的队伍压制周边，其他队伍完全不敢靠近，违背了"促进战斗"的初衷[9]。

三种解法：

1. **抬外围、遮内部**：外围高，但用高墙/建筑遮住内部视野，让中心房区的枪线锁死在墙内（如残月的地形改造器）[9]；
2. **降绝对高度**：把整体高度降下来，再加视线遮挡（奥林匹斯 S27 的船坞就是这么改的）[4]；
3. **删掉一个高点**：如果三座塔让"控全 POI"太强，就删掉一座（奥林匹斯 S27 的高塔）[4]。

### 4.5 入口即"门"

拆解文章引用过重生设计师的说法：他们希望 POI 的咽喉点像"一扇门"——玩家通过这扇门观察 POI 内部，再决定进不进[9]。门内是"不被外界打扰的死斗空间"，门外是"可以被观察、被拦截的开阔地"。

设计动作：每个 POI 的主入口，都应该满足"**看得见、进得去、退得出**"：

- 看得见：入口外有观察点，能看到 POI 内部的一部分；
- 进得去：入口不止一条，或入口内有掩体；
- 退得出：入口不是单行道，撤退时不会被反锁。

### 4.6 视线预算与玻璃

缓冲区之所以让人"敢进"，是因为它提供了信息[9]。POI 内部也一样：

- **玻璃/天窗/屋顶缺口**：让外部玩家能看到内部的一举一动，降低"不敢进"的心理门槛[9]；
- **但玻璃是双向的**：里面也能看到外面，所以玻璃位置要成对设计，不能只给进攻方信息。

设计动作：给每个 POI 标"信息窗口"——哪些位置能看进去、能看到多少、是否双向。

### 4.7 垂直分层与"两条路"

- 楼层建议 2–4 层，屋顶可达率 ≥50%；
- 每一层至少两种上下方式（楼梯 + 外部攀爬/绳索/跳塔）；
- 官方对电气区的描述是"屋顶对屋顶、街道对街道"两条战斗带同时存在[1][2]——这两条带要能互相支援，而不是各打各的。
- 奥林匹斯的 POI 是同一思路的另一种写法：开发者在作品集里把它描述为"垂直分层、迷宫式连通、高架步道"，让地面遭遇战和空中战斗交替发生[7]。

### 4.8 防御型 POI 的强度上限

有些 POI 天生易守难攻（毒气室、地形改造器）[9]。它们提供"战略多样性"——让求稳的队伍有别的选择。但强度必须封顶：

- 如果守方"进可攻、退可守、还能看全图"，这个 POI 就会吸走所有队伍；
- 如果攻方"怎么打都吃亏"，这个 POI 就会变成"没人来"。

**判断标准**：一个防御型 POI，应该让攻方"有解但代价高"，而不是"无解"。

### 4.9 POI 设计卡（模板）

每个 POI 在灰盒阶段填一张卡，评审时只看这张卡：

| 字段 | 内容 |
|---|---|
| 名称 / 一句话 Fantasy | 例如"被洪水淹了一半的发电站" |
| 战斗剖面 | CQC / 中距 / 长距 的比例（例如 6:3:1） |
| 资源等级 | S / A / B / C；主要资源类型 |
| 主区 | 地标是什么？独特战斗是什么？ |
| 次区 | 几个？各自提供什么（侧翼/休整/高点）？ |
| 入口 / 出口 | 数量、方向、风险等级 |
| 高点 | 几个？到达成本？视野范围？ |
| 保底路线 | 非机动传奇怎么走？ |
| 预期停留 | 60–90 秒 / 120–180 秒 |
| 预期队伍数 | 2 队 / 3 队 / 4 队 |
| 独特机制 | 可破坏、可封闭、载具、PVE…… |
| 风险 | 最容易被骂的点是什么？ |

> **本节验收问题**
> 1. 这个 POI 的"门"在哪？玩家能不能先观察再进入？
> 2. 守方有没有"又难攻又全图视野"的绝对点位？
> 3. 非机动传奇有没有保底路线？

## 5. 微观层：房区、掩体、可读性

### 5.1 掩体语法

把掩体分成四类，混着用：

| 类型 | 作用 | 注意 |
|---|---|---|
| **全掩体** | 完全挡住枪线 | 不能太多，否则战斗变成"躲猫猫" |
| **半掩体** | 蹲下可挡，站起可打 | 主要节奏工具 |
| **软掩体** | 可穿透/可破坏 | 制造"临时安全"，逼迫换位 |
| **视野掩体** | 只挡视线不挡子弹 | 制造"信息差" |

规则：

- 掩体要**成组**出现，间距 3–8 m，形成"移动—停留—再移动"的节奏；
- 每个掩体至少有两个退路，否则是"死亡掩体"；
- 掩体高度要有变化（蹲、站、跳），让玩家能"露头—缩回—换位"。

### 5.2 房区语法

- **入口 ≥2**；单入口房间只用于"高风险高价值"的小房间（保险库、补给室）。
- **楼梯/电梯井是垂直咽喉**：楼梯口要有"反打空间"，不能一上去就死。
- **窗户**：信息 + 投掷物 + 枪线，三重作用；窗户太多会让房区"漏风"，太少会让房区"自闭"。
- **地板/天花板可穿射**：制造"垂直压力"，让楼上楼下不能各打各的。
- **门**：可破坏/可封堵，是攻防节奏工具；门后要有"开门即交火"的心理准备，而不是"开门即死"。

### 5.3 可读性三条红线

1. **可攀爬边缘必须有视觉提示**（颜色、材质、磨损、光照），不能靠试错；
2. **可通行与不可通行**要用"光/色/形"区分，而不是用"撞墙"区分；
3. **角色轮廓优先于场景细节**：夜间图、霓虹图、复杂美术图，都必须保证"一眼能分清人和背景"。

电气区的官方访谈专门谈过夜景平衡：霓虹和其他光源经过精心配置，确保不过度影响索敌，同时保留夜景风格[3]。

### 5.4 声音与信息的预算

- 枪声、脚步、技能、载具的传播距离要设计；"信息暴露"是风险货币[11]；
- 一个区域的"信息量"要有上限：如果所有东西都在响，玩家会听觉疲劳，信息反而失效；
- 关键信息（例如敌方大招、空投、载具）应该有"独特的声音指纹"。

### 5.5 复杂美术的三条轮廓线

在任何光照下，都要能读出：

- **天际线**：远处能看出地形起伏；
- **屋顶线**：能看出哪里可上、哪里不可上；
- **门洞线**：能看出哪里能进、哪里是实墙。

> **本节验收问题**
> 1. 房区有没有"单入口 + 全视野"的死亡设计？
> 2. 可攀爬边缘，玩家能不能在不试错的情况下看出来？
> 3. 夜间/复杂光照下，角色轮廓是否仍然清晰？

## 6. 连接层：空白区、咽喉点、隔离带

### 6.1 空白区（Empty Area）

空白区不是"空无一物"，而是两个 POI 之间的**过渡地带**：没有资源、视野开阔、掩体稀少[11]。

| 参数 | 建议 | 效果 |
|---|---|---|
| 宽度 | 80–200 m | 越宽，玩家越谨慎 |
| 通过时间 | 15–35 秒（奔跑） | 太长会拖节奏，太短没有压力 |
| 掩体 | 少而精（1–2 组） | 给"赌一把"的选择 |
| 视野 | 好 | 让玩家能提前看到危险 |

两个大 POI 之间可以放"野区"作为缓冲和休整，让玩家为下一场战斗做准备[11]。

### 6.2 咽喉点五规则

咽喉点是"必经之路"，通常地形狭窄，缩小战斗范围，让通过的队伍集中注意力[11]。

1. **必经**：或者绕行代价极高（远、慢、暴露）。
2. **中段高、四周低**：架枪方有高度，但没掩体、拉不开枪线；通过方有掩体选择，可以绕[9]。
3. **攻守平级**：架枪方不能"绝对优势"，否则进圈队伍体验被摧毁[9]。
4. **多路线**：至少 2–3 条，风险收益不同（快但暴露 / 慢但安全 / 绕远但能反架）。
5. **可观察**：进入前能读到信息（门、窗口、高处），让玩家"决定要不要过"，而不是"过了才知道"。

第六条是加分项：**差异化**。如果所有过路点的攻防解法都一样，玩家不会觉得"我的战略选择有意义"[9]。

### 6.3 隔离带的三种做法

隔离带是"隔断两个资源区的高耸地带"，咽喉点是它的"开口"[9]。作用有两个：

1. 创造可控的封闭空间，隔绝远程枪线；
2. 控制交战节奏和交战预期。

三种常见做法：

| 做法 | 特点 | 适用 |
|---|---|---|
| **山脊** | 自然、可爬、可绕 | 自然地形图 |
| **裂谷** | 硬边界、不可跨越、拉长交战 | 大地图、需要"技能舞台" |
| **建筑墙/城墙** | 人工、笔直、可开门洞 | 都市图 |

### 6.4 两个反例

- **奥林匹斯：极乐空间—萨摩斯大学**。极乐空间转移只有三条路：两条高风险滑索（一条尽头直面伊卡洛斯高地），一条跳伞塔还偏向萨摩斯大学。结果是一队几乎无法反制，另一队被迫互爆，"两队基本只有一队可以出去"[9]。
- **电气区：缓冲区与交战区界限模糊**。有分析者批评它"无节制地塞满房区"，导致玩家找不到低风险转点路线，违背了 Apex"战斗爽"的核心体验[9]。

反例的共同点：**没有给"不想打"的队伍留一条"有代价但可行"的路**。Apex 的设计不是"逼所有人打"，而是"让不打的人付代价，但付得起"。

> **本节验收问题**
> 1. 每个咽喉点，是否至少有两条风险不同的路线？
> 2. 架枪方是否拥有"绝对优势"？如果是，通过方的体验是什么？
> 3. 有没有哪个 POI，被隔离带封成了"只进不出"？

## 7. 信息层：让地图自己说话

### 7.1 导航：地标、剪影、光

- **地标**：从任何位置都能看见的物体（官方描述电气区的能源银行"从任何到访之处都能看见"）[2]，用来指路；
- **剪影**：POI 的天际线要独一无二，玩家看影子就知道是哪；
- **光**：用光照方向、色温区分区域，比小地图更有效；
- **命名**：POI 名字要短、可喊、有画面感（"骷髅镇""天线"）。

### 7.2 微观目标物：在 POI 之间制造"第二类目的地"

Apex 在地图中间散布了大量"引导物"：信标、控制台、复制器、空投、武器架、保险库、PVE 巢穴[10]。它们的作用是：

- 给"不想跳 POI"的队伍一个理由；
- 把玩家从"安全路线"上拉出来；
- 制造"可争抢但不垄断"的小规模冲突。

设计动作：每条主要转点路线上，至少放一个"可选目标物"，让玩家有"绕一下"的动机。

### 7.3 可预测性：让对手能"读"你的移动

- 点对点移动（重力炮）有固定落点、有声音 → 对手能预判，第三方更"公平"[6]；
- 自由移动（跳塔、载具）方向不可预测 → 对手难预判，第三方更"随机"；
- 绳索/滑索是双向的 → 既是捷径，也是"被架的点"。

设计动作：给每种移动方式标注"可预测度"，并检查地图上"高可预测度"和"低可预测度"的比例。全低，地图会变成"随机遭遇"；全高，地图会变成"固定传送带"。

### 7.4 信息即风险

PVE、大招、黑市、空投都会暴露位置；给"暴露"定价，玩家才会做取舍[11]。

- PVE：击杀掉资源，但会发出声音、吸引第三方；
- 大招：瓦尔基里升空可以穿越地形，但尾迹和闪光很远就能看见；
- 黑市：能网罗附近资源，但被网罗的范围内资源全部浮空，等于告诉所有人"我在这"；
- 空投：资源好，但从天而降、声音巨大、只能在户外。

设计动作：每个"高收益信息装置"都要配一个"高暴露代价"，否则它会变成"无脑最优解"。

> **本节验收问题**
> 1. 一个新人落地后，能不能在 30 秒内知道"我在哪、该往哪走"？
> 2. 每条主转点路线上，有没有"可选目标物"？
> 3. 高收益目标，是否都有对应的暴露代价？

## 8. 量化标尺

> 以下区间是"可操作锚点"，来自公开地图数据、POI 数量、跑动时间与拆解文章的折算，**不是 Apex 官方数值**。用到你自己的项目时，请先用灰盒实测校准。

### 8.1 全图

| 指标 | 建议区间 | 怎么测 |
|---|---|---|
| 地图边长 | 2.2–2.7 km | 灰盒对角线 |
| 玩家密度 | 8–12 人/km² | 人数 ÷ 面积 |
| POI 总数 | 15–22 | 列表计数 |
| 高级区数量 | 4–6，多在外环 | 资源热力图 |
| 象限 POI 数 | 3–5 | 四象限计数 |
| 相邻 POI 跑动 | 25–60 秒 | 角色奔跑计时 |
| 单 POI 停留 | 60–180 秒 | 测试局录像 |
| 遭遇间隔（前中期） | 45–90 秒 | 测试局统计 |
| 决赛圈地形类型 | ≥3 | 圈层叠加图 |

### 8.2 POI

| 指标 | 建议区间 | 说明 |
|---|---|---|
| 占地 | 150–350 m 见方 | 大 POI 可到 400 m |
| 外围与内部高差 | 3–8 m（1–2 层楼） | 足以形成"高打低"，但不至于"绝对压制" |
| 入口数 | ≥2，最好 3–4 | 风险要不同 |
| 主入口视野角 | <120° | 避免"一进门被四面打" |
| 掩体间距 | 3–8 m | 形成移动节奏 |
| 内部主交战距离 | 0–30 m | 长 TTK 的闭环区 |
| POI 边缘交战距离 | 30–60 m | 缓冲区 |
| 楼层 | 2–4 层 | 屋顶可达率 ≥50% |
| 可容纳队伍 | 2–3 队（大 POI 4 队） | 超过就会"挤爆" |

### 8.3 连接层

| 指标 | 建议区间 | 说明 |
|---|---|---|
| 空白区宽度 | 80–200 m | 越宽越谨慎 |
| 空白区通过时间 | 15–35 秒 | 奔跑 |
| 咽喉点宽度 | 8–20 m | 单队可并行，两队会卡 |
| 咽喉点间距 | ≥300 m | 避免"连续卡点" |
| 每个 POI 出口路线 | 2–4 条 | 至少 1 条"低风险但绕远" |

### 8.4 微观

| 指标 | 建议 |
|---|---|
| 门宽 | 1.2–2 m |
| 窗台高 | 约 1 m（可翻越） |
| 可攀爬边缘高 | ≤2.5 m（约一层楼） |
| 房区入口 | ≥2 |
| 单入口房间 | 只用于高风险高价值 |

## 9. 制作流程

| 步骤 | 产出 | 验收问题 |
|---|---|---|
| **0. 体验目标** | 一句话"这张图让人体验到什么" + 3 条设计支柱 | 三条支柱能不能一句话说清？ |
| **1. 设计支柱** | 像世界尽头那样：密集城市 CQC / 开阔地告知对手 / 裂谷拉长交战 / 动态地形[5] | 每条支柱是否对应一个可验证的地形特征？ |
| **2. 纸面拓扑** | POI 图、连接图、全圈层叠加图 | 每个圈层都有可守点、可转路线吗？ |
| **3. 灰盒** | 比例、坡度、可达性、距离带 | 跑图时间、攀爬高度、枪线角度是否符合标尺？ |
| **4. 战斗验证** | 3v3 单 POI、6 队多 POI、跑图计时、反向跑图 | 每个 POI 能不能打完一场完整 3v3？ |
| **5. 遥测** | 落点热力图、路径热力图、死亡热力图[8] | 有没有"没人去"的区域？有没有"死得特别多"的点？ |
| **6. 美术 pass** | 可读性回归测试 | 复杂光照下，轮廓、门洞、可攀爬边缘是否清晰？ |
| **7. 上线迭代** | 真实落点、真实死亡点、真实骂声 | 哪些是设计问题，哪些是"玩家还没学会"？ |

### 关于遥测的一个坑

Jason McCord 在 2019 年分享过：开发期用热力图看落点、移动、死亡，用来判断地图流动与平衡[8]。但内部测试有一个偏差——内部玩家排队慢、死亡成本高，会打得更谨慎，导致"热点"被低估。Skull Town 在内部测试里并不算热，上线后却成了全图最热[8]。

**结论**：内部热力图只能看"结构性问题"（哪里完全没人、哪里路线断了），不能直接预测"玩家会爱去哪"。真实热度要等上线数据。

另外，灰盒阶段就要跑一遍可达性与碰撞检查：Apex 团队在 GDC 2025 专门讲过如何用 navmesh 提前发现穿模、卡点与可被利用的地形，避免"看起来能走、实际会卡"的地图拖到上线才修[15]。

## 10. 迭代手册：症状 → 处方

这张表来自奥林匹斯 S27 大改的官方复盘[4]，以及其他地图的公开经验。用法：先对症状，再选处方，最后用第 8 节的标尺验收。

| 症状 | 处方 | 官方案例 |
|---|---|---|
| 某个 POI 太强，控住就能压全图 | 降高度 + 加视线遮挡；或删掉一个高点 | 船坞降高度、加遮挡[4]；高塔三塔删一塔[4] |
| 某个 POI 太难攻，攻方无解 | 加高低差、加隧道、加跳塔，给攻方多条接近路线 | 哈蒙德实验室加地形起伏、加跳塔、加隧道[4] |
| 落地不清晰，玩家不知道落哪 | 去掉遮挡屋顶、开天窗、让资源可见 | 能量仓库去掉屋顶覆盖[4] |
| 进去容易出来难，单出口 | 加第二出口、加隧道、加绳索 | 能量仓库加出口[4]；涡轮机西侧加建筑[4] |
| 某个区域没人去 | 把外圈拉近中心、提升资源质量、加目标物 | 船坞外圈拉近、提升战利品[4] |
| 移走一个 POI 后留下空洞 | 新增 POI 填补，或改成"营地" | 新增造船厂 POI[4] |
| 区域太开阔，无处可躲 | 加掩体、加地形起伏 | 绿洲、盆栽广场加掩体[4] |
| 第三方太多、太随机 | 用可预测机动（重力炮）替代自由落点；加隔离带 | 风暴点重力炮[6] |
| 中期空转，没人打架 | 加中立目标物（信标、控制台、空投、PVE） | 各图中立目标物[10] |
| 决赛圈地形单一 | 预设 3 类终局地形，用圈层叠加图检查 | 设计流程 |
| 夜间图看不清人 | 控制霓虹亮度、保证轮廓光、做可读性回归 | 电气区夜景平衡[3] |
| 地图"太挤"，没有低风险转点 | 减少建筑密度、打通隧道、增加"缓冲区" | 电气区被批评的教训[9] |

**迭代原则**：

1. **先改结构，再改数值**：能通过加一条路解决的，不要靠调资源量解决；
2. **一次只改一个变量**：同时降高度、加掩体、移 POI，就不知道是哪个起作用；
3. **保留"旧地图记忆"**：大改要让老玩家还能认出地标，否则学习成本白费。

## 11. 竞技与排位向的额外约束

如果地图要进赛事（或高分段），额外加四条：

1. **POI 公平**：ALGS 用"预设落点 + POI 选秀"来分配起点[16]，说明 POI 之间不能有"必胜点"。设计时给每个 POI 算"资源 + 地形 + 转点"的综合分，分差控制在合理范围。
2. **多解**：每张图至少支持三种可行打法（早进圈 / 卡边 / 打野），且每种都有"能赢"的可能。
3. **观赛可读**：镜头切过去，观众能在 3 秒内看懂"谁在哪、谁有优势"。
4. **信息道具可争抢但不可垄断**：信标/控制台的位置要"值得争"，但不能让某队"出生就拿到"。

## 12. 反模式清单

1. 把"大"当"史诗"：地图越大，节奏越慢，除非用更多咽喉点/机动工具补偿[11]。
2. 空白区过大、过空：玩家会"走很久、打一架、又走很久"。
3. 高地绝对压制：又难攻又全图视野，等于劝退。
4. 单入口房区当常规设计：攻方无解，守方无敌。
5. 资源无规律、藏在角落：破坏"地图信任"，玩家开始"探索"而不是"决策"[11]。
6. 机动工具无预警、无声音：第三方变成随机事件。
7. 所有 POI 长得一样：玩家没有"去哪"的偏好，全图流量趋同。
8. 决赛圈地形单一：每局终局都像复制粘贴。
9. 为美术牺牲轮廓：夜景、雨雾、霓虹把角色吃掉。
10. 缓冲区与交战区界限模糊：玩家找不到"低风险转点"路线[9]。
11. 只有一个"最优落点"：其他落点变成"惩罚"。
12. 地图更新只会"炸掉重建"：老玩家记忆归零，学习成本浪费[12]。
13. 用"随机性"代替"节奏"：把"偶遇"当"设计"。
14. 把"掩体多"当"战斗好"：掩体太多会变成"躲猫猫"，战斗无法闭环。

## 13. 验收检查清单

### A. 全图层（16 项）

- [ ] 地图边长与人数匹配，密度在目标区间
- [ ] POI 总数、高级区数量在目标区间
- [ ] 高级区在外环成环，航线两端都有
- [ ] 中心区域没有"既富又热"
- [ ] 四象限 POI 数量均衡
- [ ] 每个 POI 至少有一种"拉动人流"的理由
- [ ] 随机 10 条航线，落点菜单完整（hot drop / 稳健 / 野区 / 高风险）
- [ ] 逐圈叠加，每圈都有可守点、可转路线
- [ ] 最后三个圈覆盖至少 3 类地形
- [ ] 地形骨架清晰（山脊/裂谷/水系/城墙至少用对一种）
- [ ] 每个区域能被"10 秒读轮廓、30 秒读路线、3 分钟读攻防"
- [ ] 转移工具"可预测度"有高有低，不是单一节奏
- [ ] 预留了 2–3 个可扩展地块
- [ ] 没有"半张图没人"的象限
- [ ] 没有"只能走一条路"的决赛圈
- [ ] 地图上有足够的"可选目标物"（信标/控制台/空投/PVE）

### B. POI 层（20 项）

- [ ] 三项职能齐全（地标/资源/战斗体验）
- [ ] 有主区、次区、外围缓冲
- [ ] 入口 ≥2，且风险不同
- [ ] 主入口"看得见、进得去、退得出"
- [ ] 外围比内部高 3–8 m
- [ ] 没有"又难攻又全图视野"的绝对点位
- [ ] 内部有 0–30 m 的近距离闭环空间
- [ ] 边缘有 30–60 m 的缓冲区
- [ ] 掩体成组，间距 3–8 m
- [ ] 每个掩体至少两个退路
- [ ] 楼层 2–4 层，屋顶可达率 ≥50%
- [ ] 每层至少两种上下方式
- [ ] 非机动传奇有保底路线
- [ ] 有"信息窗口"（玻璃/天窗/缺口），且双向
- [ ] 防御型 POI 的强度有上限
- [ ] 预期停留时长与资源量匹配
- [ ] 预期队伍数与面积匹配
- [ ] 有独特机制或独特战斗
- [ ] 能被一句话说清 Fantasy
- [ ] 最容易被骂的点，已经有对策

### C. 连接层（10 项）

- [ ] 空白区宽度、通过时间在区间内
- [ ] 空白区有 1–2 组"赌一把"的掩体
- [ ] 每个咽喉点是必经或绕行代价高
- [ ] 咽喉点中段高、四周低
- [ ] 咽喉点攻守平级，架枪方没有绝对优势
- [ ] 每个咽喉点至少 2 条风险不同的路线
- [ ] 咽喉点进入前可观察
- [ ] 每个咽喉点的攻防解法有差异
- [ ] 隔离带能切断关键远距离枪线
- [ ] 没有"只进不出"的 POI

### D. 微观点位（8 项）

- [ ] 可攀爬边缘有视觉提示
- [ ] 可通行/不可通行用光色形区分
- [ ] 角色轮廓优先于场景细节
- [ ] 夜间图霓虹不压角色
- [ ] 关键信息有独特声音指纹
- [ ] 房区没有"单入口 + 全视野"的死亡设计
- [ ] 门/窗/地板/天花板提供攻防变化
- [ ] 复杂美术下三条轮廓线清晰

## 14. 一页速查卡

**五条约束**：战斗驱动 / 长 TTK 闭环 / 无衰减靠地形 / 垂直度配保底路线 / 第三方要管理。

**四部件**：拉力（资源信息圈）→ 推力（外高内低）→ 切分（隔离带咽喉点）→ 计时（圈与转移工具）。

**一个节拍**：POI → 空白区 → 咽喉点 → 空白区 → POI。

**三条资源规则**：只在 POI 里 / 显眼 / 有规律。

**五个关键数**：2.2–2.7 km、15–22 POI、25–60 秒到下一个 POI、0–30 m 近战闭环、3 类决赛圈地形。

**五个必问**：

1. 这块地形把玩家往哪推？
2. 它让玩家看到什么？
3. 它让哪条枪线失效？
4. 不想打的人，有没有"有代价但可行"的路？
5. 非机动传奇，怎么活？

## 附录 A：从大逃杀裁剪到小规模 FPS

Apex 的方法论里，真正与"60 人 + 缩圈"绑定的只有一部分；大部分原则（推拉、门、咽喉点、可读性、可预测机动）与人数无关。下面是把 BR 概念裁剪到小规模 FPS（6v6、8v8、合作 PvE）的映射。

### A.1 概念映射表

| 大逃杀概念 | 小规模 FPS 对应物 | 保留什么 | 可以删什么 |
|---|---|---|---|
| 60 人 / 20 队 | 6v6 / 8v8 / 4 人合作 | 遭遇密度、第三方管理 | 落点菜单、选秀 |
| 缩圈 | 回合推进 / 目标点 / 关卡分段 | "不可逆的压力"和"路径收敛" | 20 分钟单局、圈层叠加 |
| POI | 竞技场 / 关卡块 / 房间组 | 三职能、推拉、门、两条路 | 资源分级、搜刮时长 |
| 空白区 / 咽喉点 | 连接走廊 / 门厅 / 桥 | 节拍、可读的必经点、攻守平级 | 大地图尺度 |
| 资源 | 拾取物 / 补给 / 技能冷却 | "拉力"（人为什么来） | 背包管理、资源等级 |
| 转移工具 | 跳跃板 / 传送门 / 滑索 | 可预测性、风险收益 | 载具、重力炮 |
| 决赛圈 | 最后据点 / 加时 / 决胜回合 | 终局地形多样性 | 圈层机制 |

**裁剪原则**：保留"压力源 + 路径收敛 + 可读的攻防"，删掉"搜刮时长 + 大地图尺度"。小规模 FPS 的节奏更快，POI 的"停留时长"要相应压缩（例如 30–60 秒），否则会显得拖。

### A.2 最小验证流程（可以直接在 Godot 里做）

1. **搭 3 个灰盒块**：两个 POI（各约 150 m × 150 m）+ 一条咽喉点连接。比例保持 1 unit = 1 m，玩家身高按 1.8 m 放，别用"看起来差不多"的比例。
2. **放 6 个出生点**：每个 POI 两个入口、咽喉点两端各一个。跑三遍：A→B 直穿、A→B 绕行、B→A 反向。
3. **测四个数**：POI 间跑动时间、首次交火时间、单场战斗时长、转点死亡率。
4. **验收阈值（示例，需校准）**：首次交火 < 30 秒；单 POI 战斗 20–60 秒；转点死亡率 < 30%；三条路线的时间差 < 15 秒（否则会有一条"唯一最优"）。
5. **只改一个变量再测**：例如只把咽喉点加宽 4 m，看转点死亡率是否下降。一次改多个变量，就不知道是哪个起作用（同第 10 节）。

### A.3 Godot 灰盒提示

- 用 `CSGCombiner3D` 快速搭块，`GridMap` 做重复掩体；灰盒阶段不要贴图，用纯色材质区分"可走 / 不可走 / 可攀爬"。
- 用 `WorldEnvironment` 做可读性回归：白天、夜晚、雾天各跑一遍，检查角色轮廓是否还清晰。
- 用 `Label3D` 在场景里标"入口 / 高点 / 咽喉点 / 可攀爬边缘"，方便评审时指着说。
- 用简单的脚本做跑图计时：起点 `Area3D` 触发开始，终点触发打印 `Time.get_ticks_msec()` 差值。
- 用 `NavigationRegion3D` 检查可达性，但**不要**用它代替人工跑图——navmesh 会掩盖跳跃、攀爬、卡脚的问题。

### A.4 原型阶段"先别做"的三件事

1. **先别做全图**：先做"1 个 POI + 1 条咽喉点 + 1 段空白区"，验证节拍是否成立。全图是节拍的放大器，节拍不成立，放大只会更糟。
2. **先别做资源系统**：先验证"战斗闭环"是否好玩（掩体、垂直、TTK、复活）。资源是拉力，不是战斗本身。
3. **先别堆垂直度**：先验证"非机动角色有路可走"。垂直度是 Apex 的招牌，也是最容易把地图做成"蜘蛛侠专属"的陷阱。
